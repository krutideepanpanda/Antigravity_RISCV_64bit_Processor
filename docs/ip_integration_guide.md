# RV64I Core IP Integration Guide

## 1. Architectural Overview

The `rv64i_cpu` core is a fully synthesizable, 5-stage pipelined 64-bit RISC-V processor implementing the RV64I base integer instruction set architecture. To facilitate seamless integration into standard System-on-Chip (SoC) interconnects, the package provides a standalone bridge module, [rv64i_axi4lite_bridge](file:///home/bazzite/Antigravity_RISCV_64bit_Processor/rtl/ip_block/rv64i_axi4lite_bridge.v), which converts the processor's internal instruction fetch and data read/write buses into a fully compliant AMBA AXI4-Lite master interface.

The top-level wrappers and packaging descriptors included in this IP block release are:
* [rv64i_axi4lite_bridge.v](file:///home/bazzite/Antigravity_RISCV_64bit_Processor/rtl/ip_block/rv64i_axi4lite_bridge.v): AXI4-Lite Master/Slave interface bridge with internal arbitration and pipeline stalling logic.
* [asic_top.v](file:///home/bazzite/Antigravity_RISCV_64bit_Processor/rtl/asic_top.v): Registered ASIC top-level wrapper optimized for static timing analysis (STA) and Wishbone/SRAM interfacing.
* [rv64i_cpu_ip.xml](file:///home/bazzite/Antigravity_RISCV_64bit_Processor/ip/rv64i_cpu_ip.xml): IEEE 1685-2014 IP-XACT component descriptor for automated EDA tool flow ingestion.
* [rv64i_core.core](file:///home/bazzite/Antigravity_RISCV_64bit_Processor/ip/rv64i_core.core): FuseSoC package descriptor (CAPI=2 format) for automated dependency tracking and multi-target builds.

## 2. Signal Pinout Specification

### 2.1 Clock and Reset Interface

| Port Name | Direction | Width | Description |
| :--- | :--- | :--- | :--- |
| `clk` | Input | 1 | Master system clock. Rising-edge triggered for all sequential registers. |
| `rst_n` | Input | 1 | Active-low asynchronous/synchronous system reset (`aresetn` compatible). |

### 2.2 CPU Slave Bus Interface (to/from Processor Core)

| Port Name | Direction | Width | Description |
| :--- | :--- | :--- | :--- |
| `imem_addr` | Input | 64 | Instruction fetch address generated by the IF stage Program Counter. |
| `imem_req` | Input | 1 | Instruction fetch request enable signal. |
| `imem_rdata` | Output | 32 | 32-bit instruction read data returned to the IF/ID pipeline register. |
| `imem_valid` | Output | 1 | Instruction fetch completion flag indicating valid data on `imem_rdata`. |
| `imem_stall` | Output | 1 | Pipeline stall request asserted during instruction fetch bus cycles. |
| `dmem_addr` | Input | 64 | Data memory target address from the EX/MEM pipeline stage. |
| `dmem_wdata` | Input | 64 | Formatted write data from store instructions (`SB`, `SH`, `SW`, `SD`). |
| `dmem_we` | Input | 1 | Data memory write enable strobe. |
| `dmem_re` | Input | 1 | Data memory read enable strobe. |
| `dmem_be` | Input | 8 | Byte enable byte-mask corresponding to store operations. |
| `dmem_rdata` | Output | 64 | Raw data read from memory for load instructions (`LB`, `LH`, `LW`, `LD`, etc.). |
| `dmem_valid` | Output | 1 | Data access completion flag indicating valid read data or store completion. |
| `dmem_stall` | Output | 1 | Pipeline stall request asserted during data memory bus cycles. |
| `cpu_stall` | Output | 1 | Unified global pipeline stall output connected to hazard unit and PC registers. |

### 2.3 AMBA AXI4-Lite Master Interface (System Bus)

| Port Name | Direction | Width | Description |
| :--- | :--- | :--- | :--- |

| `m_axi_awprot` | Output | 3 | Write Address Channel: Protection attributes (default: `3'b000`). |
| `m_axi_awvalid` | Output | 1 | Write Address Channel: Valid handshake signal. |
| `m_axi_awready` | Input | 1 | Write Address Channel: Ready handshake signal from slave. |
| `m_axi_wdata` | Output | 64 | Write Data Channel: Write payload data. |
| `m_axi_wstrb` | Output | 8 | Write Data Channel: Byte lane strobe mask. |
| `m_axi_wvalid` | Output | 1 | Write Data Channel: Valid handshake signal. |
| `m_axi_wready` | Input | 1 | Write Data Channel: Ready handshake signal from slave. |
| `m_axi_bresp` | Input | 2 | Write Response Channel: Status response code (`2'b00` = OKAY). |

| `m_axi_bready` | Output | 1 | Write Response Channel: Ready handshake signal from master. |

| `m_axi_rready` | Output | 1 | Read Data Channel: Ready handshake signal from master. |

## 3. Memory Map and Address Space Allocation

The processor core operates over a unified 64-bit physical address space (`0x0000000000000000` to `0xFFFFFFFFFFFFFFFF`). The [rv64i_axi4lite_bridge](file:///home/bazzite/Antigravity_RISCV_64bit_Processor/rtl/ip_block/rv64i_axi4lite_bridge.v) implements fixed priority arbitration:

1. **Data Memory Writes (`dmem_we`)**: Highest priority. Ensures store buffers are committed to memory without introducing artificial write-after-write hazards.
2. **Data Memory Reads (`dmem_re`)**: Second priority. Resolves load operations required by instructions in the execution stage.
3. **Instruction Memory Reads (`imem_req`)**: Third priority. Instruction fetch occurs whenever the Program Counter transitions to a new address that has not yet been fetched.

### Byte Alignment Rules
* Instruction fetches are naturally aligned on 4-byte boundaries (`imem_addr[1:0] == 2'b00`).
* Data memory accesses support variable byte widths selected via `dmem_be`:
  * Byte (`8-bit`): 1 active strobe bit in `m_axi_wstrb`.
  * Halfword (`16-bit`): 2 active strobe bits in `m_axi_wstrb`.
  * Word (`32-bit`): 4 active strobe bits in `m_axi_wstrb`.
  * Doubleword (`64-bit`): All 8 strobe bits active (`8'b11111111`).

## 4. Clocking and Reset Requirements

### 4.1 Clock Specification
* **Domain**: Single synchronous clock domain (`clk`).
* **Frequency Target**: Up to 50 MHz on SkyWater 130nm (`sky130_fd_sc_hd` library) under nominal operating conditions (1.8V, 25 C).
* **Duty Cycle**: Nominal 50% duty cycle required.

### 4.2 Reset Specification
* **Signal**: `rst_n` (active-low).
* **Behavior**: When `rst_n` is driven low (`0`), all internal pipeline registers, state machines, and AXI4-Lite master output strobes (`m_axi_awvalid`, `m_axi_wvalid`, `m_axi_arvalid`) are asynchronously or synchronously forced to `0` within one clock cycle.
* **Release Timing**: `rst_n` deassertion must be synchronized to the rising edge of `clk` to prevent metastable state transitions in the instruction fetch stage.

## 5. Synthesis and Physical Design Integration

### 5.1 Automated Toolchain Ingestion via FuseSoC
The IP block is packaged with a FuseSoC core descriptor located at [rv64i_core.core](file:///home/bazzite/Antigravity_RISCV_64bit_Processor/ip/rv64i_core.core). To integrate the core into an external FPGA or ASIC build tree:

```bash
# Add the local IP repository to FuseSoC
fusesoc library add rv64i_core /home/bazzite/Antigravity_RISCV_64bit_Processor/ip/

# Run linting across all packaged Verilog RTL files
fusesoc run --target=lint openlane:ip:rv64i_core:1.0.0

# Simulate the testbench top-level target
fusesoc run --target=sim openlane:ip:rv64i_core:1.0.0
```

### 5.2 EDA Tool Import via IP-XACT
For commercial EDA environments (such as Vivado IP Integrator, Synopsys CoreBuilder, or ARM Socrates), import the IEEE 1685-2014 descriptor located at [rv64i_cpu_ip.xml](file:///home/bazzite/Antigravity_RISCV_64bit_Processor/ip/rv64i_cpu_ip.xml). The XML descriptor automatically maps logical AXI4-Lite interfaces to the underlying Verilog ports and attaches all required source files from `rtl/core/` and `rtl/ip_block/`.

### 5.3 OpenLane ASIC Synthesis Workflow
When targeting ASIC tape-out via OpenLane, point the flow configuration to [asic_top.v](file:///home/bazzite/Antigravity_RISCV_64bit_Processor/rtl/asic_top.v) as the top-level module. Ensure that the include directory `rtl/include` is explicitly added to `VERILOG_INCLUDE_DIRS` in `config.json` so that [rv64i_types.vh](file:///home/bazzite/Antigravity_RISCV_64bit_Processor/rtl/include/rv64i_types.vh) is resolved during Verific/Yosys elaboration.
